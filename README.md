# CS-305-Software-Security

# Software Security Assessment — Artemis Financial

|Module quetions|My response| 
|-----:|-----------|
|1. Briefly summarize your client, Artemis Financial, and its software requirements. Who was the client? What issue did the company want you to address?| Artemis Financial is a client representing a mid-sized financial services company responsible for sensitive client data. The primary software requirement was to ensure that their core application, a REST-based financial service, was free from known vulnerabilities, particularly those arising from third-party dependencies. The key issue Artemis wanted addressed was the risk posed by outdated or insecure libraries commonly included during rapid development, which could lead to data breaches or compliance failures.|
|2. What did you do well when you found your client’s software security vulnerabilities? Why is it important to code securely? What value does software security add to a company’s overall well-being?| Upon detecting software vulnerabilities through tools like the OWASP Dependency-Check Maven plugin, effective actions included documenting vulnerabilities, distinguishing false positives, and communicating risk clearly to stakeholders. Secure coding is critical because it proactively reduces both the likelihood and impact of security incidents. Investing in software security protects sensitive information, ensures compliance, preserves trust, and ultimately supports the company’s reputation and business continuity.|
|3. Which part of the vulnerability assessment was challenging or helpful to you?| One notable challenge during the assessment was distinguishing genuine vulnerabilities from false positives, especially when third-party dependencies were flagged incorrectly. This required both technical research and careful judgment. However, the process was also educational, improving understanding of how modern supply chains introduce risk and how to leverage automated tools for continuous monitoring.|
|4. How did you increase layers of security? In the future, what would you use to assess vulnerabilities and decide which mitigation techniques to use?| Security was improved by using tools like OWASP Dependency-Check, which added an automated, repeatable auditing layer to the build process. Going forward, a combination of static analysis tools, composition analysis (such as Snyk, Sonatype, or continued OWASP Dependency-Check), and adopting defense-in-depth strategies (such as regular patching and code reviews), should be used to assess and mitigate vulnerabilities more comprehensively.|
|5. How did you make certain the code and software application were functional and secure? After refactoring the code, how did you check to see whether you introduced new vulnerabilities?| To ensure code remained both functional and secure, each change or refactoring was followed by re-running automated dependency scans and existing software tests. This continuous cycle meant that if mistakes or new vulnerabilities were introduced, they were promptly detected. After refactoring, specifically checking the dependency-check report and unit test results confirmed that the software maintained both security and operational requirements.|
|6. What resources, tools, or coding practices did you use that might be helpful in future assignments or tasks?| Key resources and tools included the OWASP Dependency-Check Maven plugin for vulnerability scanning, informative security documentation, and suppression files for managing known false positives. Coding best practices involved keeping dependencies up to date, using version pinning, and adopting secure coding guidelines recommended by OWASP and other respected organizations.|
|7. Employers sometimes ask for examples of work that you have successfully completed to show your skills, knowledge, and experience. What might you show future employers from this assignment?| For future employers, showcase this project’s artifacts—especially how automated security tools were integrated (such as your pom.xml modifications), suppression.xml for managing false positives, vulnerability reports before and after scans, and documentation explaining decision-making. Demonstrating both hands-on technical skills and clear security rationale provides concrete evidence of your ability to keep systems secure in practice.|
